# 图片优化 - 查看原图需求（待定）

## 需求描述

当前实现：前端上传前自动压缩图片，只上传压缩后的一张图片。

用户反馈：压缩后图片质量仍有损失，影响查看。

用户建议：笔记页面默认显示压缩图片节省流量，但用户点击查看原图后，记住用户选择，以后打开笔记都直接显示原图。

## 方案设计

### 核心思路

- 首次加载：默认显示压缩图 → 节省流量，加载快
- 用户交互：点击图片 → 切换为原图 → 记录用户选择到 localStorage
- 后续打开：直接显示原图 → 不用再点一次

### 实现细节

**前端：**
1. 上传图片时，生成一张压缩图（限制最大尺寸 + 压缩质量）
2. 同时上传压缩图和原图两张图片到后端
3. 后端返回两个 URL：压缩图 URL + 原图 URL
4. 在内容中插入自定义标记：
   ```html
   <img 
     data-compressed="压缩图URL" 
     data-original="原图URL" 
     alt="图片名称"
     class="optimized-image"
   >
   ```
5. 笔记渲染时，自定义图片组件处理：
   - 检查 `localStorage` 是否有 `viewed-original-{key}` 标记
   - 如果有 → 直接显示原图
   - 如果没有 → 显示压缩图，点击图片时切换到原图，并保存标记到 localStorage

**后端：**
1. 修改 `/api/upload` 接口，支持同时上传或先后上传两张图片
2. 保存两个文件：原图 `{filename}.{ext}`，压缩图 `{filename}_compressed.{ext}`
3. 返回 JSON：`{ success: true, url: 压缩图URL, originalUrl: 原图URL }`

### 优缺点

| 优点 | 缺点 |
|------|------|
| 首次加载省流量 | 需要存储两份图片，占用更多服务器空间 |
| 用户选择永久记住 | 前后端都需要修改，工作量稍大 |
| 交互简单自然，不用额外按钮 | |

### 替代方案

**方案一：只存原图，CSS 缩放显示**
- 只上传原图，笔记显示时用 CSS `max-width: 100%` 限制显示尺寸
- 优点：只存一份，不占空间；实现简单
- 缺点：首次加载仍然要下载原图，流量浪费依旧存在

**方案二：点击图片打开新标签看原图**
- 笔记里一直显示压缩图
- 点击图片在新标签打开原图
- 优点：实现简单，只存一张图（压缩后的）
- 缺点：每次看原图都要重新点开，不方便
